# bpflite — eBPF Syscall & Process Tracer

## Overview

`bpflite` is a lightweight, CO-RE (Compile Once, Run Everywhere) eBPF-based
tracer written in Go. It attaches to kernel tracepoints to observe process
lifecycle and file activity in real time, streaming events to a terminal UI
or as structured JSON for scripting/piping.

No BCC. No clang-at-runtime. No kernel headers on the target machine.
Just a statically-embedded eBPF object file loaded via `cilium/ebpf`.

**Why this exists:** most Go portfolios are full of CRUD APIs and CLI
wrappers. This is a kernel-adjacent systems tool — it demonstrates
comfort with the syscall boundary, tracepoints/kprobes, ring buffers, and
low-level Linux internals, which is exactly what platform engineering /
SRE / infra tooling roles filter for.

---

## Target environment

- Linux kernel 5.x+ with BTF support (`/sys/kernel/btf/vmlinux` must exist)
- Verified working on: Linux, kernel 6.x
- Requires root or `CAP_BPF` + `CAP_PERFMON` to load/attach programs

---

## Scope (MVP — v0.1)

Ship ONE vertical slice cleanly before expanding. Priority order:

1. **`execve` tracer** — every new process spawned system-wide
   - PID, PPID, UID, command, full argv
2. **`openat` tracer** — files opened by a given process/PID filter
3. Live terminal view (Bubble Tea) + `--json` flag for stdout piping

Explicitly OUT of scope for v0.1 (future milestones):

- Network tracing (TCP connect/accept/close) — this becomes v0.2
- Per-process aggregation / historical SQLite logging — v0.3
- Any eBPF program that writes/modifies data (stay read-only observability
  for now — no seccomp, no packet mangling)

## Architecture

```
┌──────────────────────┐
│  eBPF program (C)     │   tracepoint/syscalls/sys_enter_execve
│  probe.bpf.c           │   tracepoint/syscalls/sys_enter_openat
│  compiled via clang    │   → writes event struct to ring buffer
└──────────┬─────────────┘
           │ go:generate bpf2go (embeds .o into Go binary at build time)
┌──────────▼─────────────┐
│  Go loader              │   cilium/ebpf: load, attach, read ringbuf
│  internal/loader/        │   decode raw bytes → typed Go event structs
└──────────┬─────────────┘
           │ channel of events
┌──────────▼─────────────┐
│  Output layer            │
│  ├─ TUI (Bubble Tea)      │   live scrollable table, filter by name/pid
│  └─ JSON stdout           │   one event per line, pipeable to jq
└───────────────────────────┘
```

## Stack

| Component        | Choice                          | Why |
|-------------------|----------------------------------|-----|
| eBPF loader        | `github.com/cilium/ebpf`         | Pure Go, no CGo, CO-RE support out of the box |
| Codegen            | `bpf2go` (part of cilium/ebpf)   | Compiles `.c` → `.o`, embeds as Go byte slice |
| TUI                | `charmbracelet/bubbletea`         | Already fluent from go-ytm |
| CLI framework      | `spf13/cobra`                     | Consistent with your other tools |
| Event transport    | eBPF ring buffer (`BPF_MAP_TYPE_RINGBUF`) | Lower overhead than perf buffer, kernel 5.8+ |

## Build pipeline

```bash
# 1. Generate vmlinux.h once (BTF-derived kernel type header)
bpftool btf dump file /sys/kernel/btf/vmlinux format c > bpf/vmlinux.h

# 2. go:generate directive in a Go file triggers bpf2go
//go:generate go run github.com/cilium/ebpf/cmd/bpf2go -cc clang \
    -cflags "-O2 -g -Wall" probe bpf/probe.bpf.c -- -I./bpf

go generate ./...

# 3. Normal Go build — the compiled eBPF bytecode is embedded, so the
#    final binary is fully self-contained (no runtime clang dependency)
go build -o bpflite ./cmd/bpflite
```

## Critical rules for the C struct ↔ Go struct boundary

- Every field in the eBPF ring buffer event struct MUST match byte-for-byte
  with the Go struct that decodes it (same field order, same sizes, explicit
  padding where needed). Use `binary.Read` with `binary.LittleEndian`, or
  `encoding/binary` unsafe cast — pick one and be consistent.
- Fixed-size char arrays in C (e.g. `char comm[16]`) map to `[16]byte` in Go,
  not `string` — trim null bytes after read.
- Never pass Go pointers into eBPF map operations across cgo boundaries;
  `cilium/ebpf` handles this internally, don't fight it with raw syscalls.
